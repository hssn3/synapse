# DEPLOYMENT — چک‌لیست استقرار (Production)

> وضعیت فعلی: **دیپلوی production ندارد** (سرویس قبلی Railway از کار افتاده — تأیید ۱۴۰۵/۰۷/۲۰).
> این چک‌لیست برای هر provider جدید (Railway / VPS+Docker / هر ابری) استفاده شود.
> هیچ مرحله‌ای اینجا «انجام‌شده» فرض نمی‌شود مگر با شاهد اجرا.

## A) پیش از استقرار

- [ ] **راز نشست (JWT_SECRET)** — اجباری و بدون هیچ مقدار پیش‌فرضی در فایل‌های مخزن:
      تولید مقدار: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`
      · `docker-compose.yml` مقدار راز را فقط از محیط می‌خواهد؛ نبودنش **پیش از** بالا آمدن
        سرویس با پیام «JWT_SECRET is required …» و کد خروج غیرصفر رد می‌شود (نحو الزامِ compose).
      · محافظ دوم `src/config/app.js` است: در `NODE_ENV=production` رازِ غایب/پلیس‌هولدر/
        کوتاه‌تر از ۳۲ کاراکتر را با خط `FATAL` و `exit(1)` رد می‌کند (تستِ AC-08 همین را می‌سنجد).
      · مقدار از محیط سرور یا `.env` (که در گیت نیست) خوانده شود — هرگز داخل فایل مخزن نباشد.
- [ ] **DATA_DIR** روی والیوم ماندگار (دیتابیس + uploads + backups با هم).
      اگر ست نشود، هر redeploy داده را می‌برد.
- [ ] **NODE_ENV=production** + HTTPS واقعی (برای کوکی Secure و CSP).
- [ ] **PORT** همان پورتی که proxy/nginx به آن اشاره می‌کند (compose پیش‌فرض ۳۰۰۰ را می‌بندد).
- [ ] **BASE_URL** دامنه‌ی عمومی (برای لینک‌های QR/ایمیل).
- [ ] کلید LLM دستیار: از پنل سوپرادمین یا `GEMINI_API_KEY` + `npm run assistant:key`.
- [ ] رمزهای دموی پیش‌فرضِ دیتابیس تازه (hospital3_admin / SuperAdmin@2026) **عوض شوند**.
- [ ] `require_password` برای ورود کاشی‌ای روشن شود (پنل سوپرادمین → تنظیمات).
- [ ] SMTP/SMS در صورت نیاز ریمایندرها (بدون آن، فقط درون کارتابل).

### تفکیک محیط‌ها (dev / preview / production)

- هر محیط: **راز جدا، `.env` جدا، `DATA_DIR` جدا**. رازِ مشترک بین محیط‌ها مرز امنیتی را پاک
  می‌کند: نشستی که در dev صادر شده، با همان کلید در production هم معتبر است.
- **دیتابیس توسعه/پیش‌نمایش هرگز به production وصل نمی‌شود**: نه با mount کردن والیوم آن روی
  سرویس تولید، نه با کپی `database/hospital.db` دموی مخزن روی والیوم تولید، نه با مشترک
  گذاشتن `DATA_DIR`. داده‌ی دمو با رمزهای عمومیِ شناخته‌شده است.
- production هرگز با `NODE_ENV` غیر از `production` بالا نیاید؛ dev/preview با `NODE_ENV=development`
  تا محافظ راز و کوکی Secure مسیر اشتباه را نگیرند.

## B) استقرار (Docker)

```bash
# ۱) فایل محیط را بسازید و پر کنید (مقادیر واقعی — هرگز در گیت)
cp .env.example .env      # راز نشست را در همین فایل بگذارید (گام A)
#    تا وقتی راز پر نشده، بوت عمداً بالا نمی‌آید — این طبیعی است.

# ۲) پیش‌پرواز: اعتبارسنجی ترکیب، بدون بالا آوردن هیچ سرویسی
docker compose config --quiet
#    بدون راز ⇒ خطا و کد خروج غیرصفر، پیش از هر build/up
#    توجه: همین دستور بدون --quiet مقدار رازِ محیط را چاپ می‌کند؛ در ترمینال مشترک اجرا نشود.

# ۳) ساخت و بالا آوردن
docker compose up -d --build

# ۴) صبر برای بوت اول (زنجیره‌ی seed/migration روی والیوم خالی ~۱-۲ دقیقه)
docker compose logs -f app   # تا پیام "Hospital Platform running on port 3000"

# ۵) سلامت
curl -fsS http://localhost:3000/healthz
```

- فایل nginx مرجع: `docs/nginx.conf` (بلوک HTTPS بعد از certbot از کامنت خارج شود).
- بکاپ خودکار روزانه: فعال است (`AUTO_BACKUP_RETENTION_DAYS`).
- برای VPS بدون Docker: `npm ci --omit=dev && npm run init-db && npm start` پشت systemd/PM2 + nginx
  (راز نشست و `DATA_DIR` در EnvironmentFile فایل سرویس/PM2 بمانند، نه در مخزن).

## C) پس از استقرار (Smoke واقعی)

- [ ] `SMOKE_BASE_URL=... node --test tests/rbac-endpoint-matrix.test.js` → ۱۵/۱۵

- [ ] آزمون بازگردانی بکاپ روی یک محیط جدا (حداقل یک‌بار).
- [ ] بازبینی لاگ خطای بوت از پنل سوپرادمین (`/api/super/error-log`) — صفر خطای غیرمنتظره.

## D) بازگردانی (Rollback)

- کد: برگشت به ایمیج قبلی (`docker compose up -d --build` با تگ قبلی) یا `git revert` (بدون force).
- داده: `npm run restore-db` از آخرین بکاپ سالم — **فقط پس از بکاپ از وضعیت فعلی**.
- در هر رخداد: ثبت در `docs/PROGRESS.md` (چه شد، چه کردیم، نتیجه).

## E) ممنوعیت‌ها

- هیچ دیپلوی production از این محیط توسعه بدون **مجوز صریح کتبی کارفرما**.
- **دیتابیس توسعه/پیش‌نمایش هرگز به production وصل نمی‌شود** (قید صریح، بدون استثنا): نه mount
  کردن والیوم dev روی سرویس تولید، نه کپی دیتابیس دمو، نه `DATA_DIR` مشترک.
- هیچ رازی (راز نشست، کلید LLM، SMTP، SMS) در فایل‌های گیت/اسکرین‌شات/پرامپت AI نرود؛
  `.env.example` فقط نام متغیرها و روش تولید راز را دارد و هیچ مقدار نمونه‌ای در آن نیست.
- هرگز داده‌ی بیمار واقعی در مخزن/اسکرین‌شات/پرامپت AI نگذارید.
