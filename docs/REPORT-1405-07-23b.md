## ۴) RBAC و کنترل‌های امنیتی
- **بازرسی مجوزدهی روی ۴۷۳ مسیر/۱۳۰ فایل:** فهرست A = **۱۶۶** «authRequired بدون نگهبان استاندارد» (هم‌خوان با رقم نشست قبل)؛ فهرست B = **۵۳** «بدون auth» که پس از بازبینی: ۴۶ = کل `/api/super/*` پشت `superAdminRequired` (تأیید سورس `super.js:39`) و ۷ = مسیرهای auth عمدی (login/logout/dev با گارد محیطی).
- **۲۲ نمونهٔ دستی:** اسکن تک‌خطی سوگیری منفی دارد — نمونه‌ها غالباً نگهبان درون‌تابعی/میان‌افزار نام‌دار داشتند (`authorize()`، `canEditDocuments`، `shiftAccessUnit`، `nrsCanManage`، `hasPerm`، `canApprovePrograms`، `canEditPeriod`، `mgmtCanManage`).
- **کاندیدهای بازبینی دقیق‌تر (تأییدنشده، صریح):** `assistant-enterprise/chat` (بدهی مستند دو-منبع مجوز)، خانوادهٔ `/api/kpis*`، `/api/export/*.xlsx`، چند read اکریدیشن/داشبورد — فعلاً فقط `authRequired + hospitalScope`.
- کنترل‌های تأییدشدهٔ بیس‌لاین: rate-limit ورودها (`security.js:86-108`)، helmet/CSP، کوکی httpOnly، بلاک‌لیست logout، آپلود whitelist + ۵MB، `client_token` ضد ارسال تکراری.
