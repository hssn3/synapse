## ۴) داده و سوئیچ

- `database/accreditation-standards-data.json` = دادهٔ نسل ششم (کلیدها: `source`, `source2`, `الف`, `ب`, `ج`).
  نسخهٔ پنجم در تاریخچهٔ گیت است: `git show <کامیت پیش از مهاجرت>:database/accreditation-standards-data.json`.
- هر سنجه: `code`, `standard_code`, `statement`, `level`, `weight`, `patient_safety_flag`, `page`, `steps[]`, `notes`, `detail_text`
  (گام‌ها در `detail_text` با جداکنندهٔ `U+F0A7` — قرارداد `parseGuide` فرانت‌اند؛ تغییرش ندهید).
- سوئیچ درجا: `database/seed-accreditation-v6.js` — تراکنشی و idempotent:
  - **مارکر**: وجود سنجهٔ `ج-1-5-18` یعنی قبلاً سوئیچ شده → رد شو.
    (چرا این مارکر: ویرایش پنجم فقط `ج-1-5-1..3` داشت؛ `ب-1-10-1` مارکر خوبی نیست چون در پنجم هم وجود داشت — استاندارد آموزش.)
  - ارجاع‌های کد-محور (measure_status، controlled_documents، checklists، …) قبل از حذف جمع و بعد از درج با کلید `level_type|code` بازنگاشت می‌شوند؛
    کدِ بازنشسته → NULL (ردیف‌های وابسته کاسکید می‌شوند — اطلاعات بی‌معنا نگه نمی‌داریم).
  - اجرای واقعی (دیتابیس دمو): **۲۹۱ ارجاع منتقل**، **۲۴۱ ارجاع به کد بازنشسته (پاک/تهی)**؛
    `measure_status` باقی‌مانده ۲۷۹ ردیف، همه متصل به سنجه‌های زنده، صفر یتیم.
  - تنظیمات نوشته‌شده: `accreditation_edition='6'` و `latin_runs_unreversed_v1='1'`.
- جانمایی در بوت (`src/app.js`، حدود خط ۱۷۰): بعد از `seed-sections-documents` و **قبل از** `seed-standard-titles`
  (چرا: عنوان‌ها/ترتیب/نقش‌ها باید روی درخت ششم بنشینند).
- زنجیرهٔ بوت پس از سوئیچ: `seed-standard-titles` عنوان ۸۸ استاندارد را از JSON می‌گذارد؛ `seed-section-tree-fix` ترتیب و آیکونِ ۵۰۴ گره را کامل می‌کند؛
  `migrate-roles` مسئول هر سنجه را از `AXIS_ROLE` جدید می‌زند (ب-۹→clinical_supervisor؛ ب-۱۰ حذف)؛ `seed-eval-methods` روش ارزیابی ۳۹۵ سنجه را استنتاج می‌کند.
- ترمیم متن: پاسِ بوت `seed-repair-measure-text` روی ۳۹۷ ردیف / ۵۸۷ فیلد نرمال‌سازی کرد (نیم‌فاصله/فاصله)؛
  برای یکسان‌شدن دو منبع، همان پاس روی JSON مرجع نیز اجرا شد: `node database/seed-repair-measure-text.js --json` → اکنون **صفر اختلاف** بین JSON و DB.
- **تلهٔ رفع‌شده**: `seed-standards-titles-fix` (قدیمی) عنوان‌های `الف-3-2` و `ب-1-1` را با متنِ ویرایش پنجم بازنویسی می‌کرد (چون بعد از `seed-standard-titles` اجرا می‌شود).
  اکنون همین فایل به متن نسل ششم همگام است و ردیف `ج-1-6` (که در ششم وجود ندارد) حذف شد.

## ۸) بازگردانی (rollback)

- دیتابیس: بکاپ پیش از سوئیچ + بکاپ خودکار روزانهٔ `BackupCron`؛ بازگشت = برگرداندن فایل DB.
- داده: نسخهٔ پنجم JSON در تاریخچهٔ گیت است؛ `git checkout <کامیت قبلی> -- database/accreditation-standards-data.json`.
- نکته: سوئیچ فقط یک‌بار (مارکر) اجرا می‌شود؛ بازگشت به ویرایش پنجم نیازمند بازگردانی DB است، نه فقط برگرداندن فایل JSON.
