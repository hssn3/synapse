# REQUIREMENTS — معیارهای پذیرش (Acceptance Criteria)

> طبق گردش‌کار سازمانی: هر تغییرِ معنادار معیار پذیرشِ قابل‌اجرا دارد.
> قالب: Given/When/Then؛ هر مورد به یک تست یا پروبِ مشخص نگاشت می‌شود.

## AC-01 — ورود امن (RBAC)
- **Given** کاربر مهمان (بدون کوکی)
- **When** `GET /api/dashboard` و `GET /api/accreditation/tree` صدا زده شود
- **Then** پاسخ `401` است.
- **نگاشت تست:** `scripts/smoke-test.js` (probe ۲) — اجرا: سبز ✅

## AC-02 — دسترسی نقش پرستار محدود است
- **Given** نشست فعال با نقش `staff_nurse`
- **When** حذف کاربر یا خواندن فهرست کاربران امتحان شود
- **Then** عملیات مدیریتی رد (`403`) می‌شود (Fail-Closed).
- **نگاشت تست:** `tests/rbac-matrix.test.js` (۱۴ ادعا) + تست دستی HTTP (۱۴۰۵/۰۷/۲۰) — سبز ✅

## AC-03 — ورود کاشی‌ای سمتی
- **Given** صفحه‌ی ورود بیمارستان
- **When** کاربر روی سمت «مدیر پرستاری» کلیک می‌کند (require_password خاموش دمو)
- **Then** نشست معتبر می‌گیرد و داشبورد مدیریت پرستاری رندر می‌شود.
- **نگاشت تست:** QA ۲۴ نقش (`qa-all-roles.js`) — ۲۴/۲۴ سبز ✅

## AC-04 — پوسته‌ی اپ‌مانند موبایل
- **Given** کاربر واردشده در ویوپورت 390px
- **When** هر صفحه‌ی مجاز باز شود
- **Then** نوار تب پایین ثابت با دکمه‌ی مرکزی «دانا» دیده می‌شود؛ هدر/فوتر سراسری پنهان است؛ محتوای قابل‌کلیک زیر نوار پنهان نمی‌ماند (در حالت اسکرول ته).
- **نگاشت تست:** `final-mobile-test.js` + `scroll-bottom-test.js` (۹ صفحه) — سبز ✅

## AC-05 — پوسته‌ی دسکتاپ
- **Given** کاربر واردشده در 1440px
- **When** هر صفحه باز شود
- **Then** سایدبار راست تمام‌قد است؛ دکمه‌های شناور پایین-راست‌اند؛ تب‌بار موبایل دیده نمی‌شود؛ هدر/فوتر پنهان.
- **نگاشت تست:** `verify-current.js` (dسکتاپ) + تأیید بصری — سبز ✅

## AC-06 — اسنپ‌شات دمو بدون راز
- **Given** فایل `database/demo-snapshot/hospital-demo.db.gz` از مخزن عمومی
- **When** باز و اسکن شود
- **Then** هیچ کلید/توکنی (AIza/ghp/sk-/pat) ندارد؛ داده‌ی کلینیکی ساختگی است.
- **نگاشت تست:** اسکن بایتی (python regex) — ۰ یافته ✅

## AC-07 — اسکریپت کلید دانا
- **Given** `GEMINI_API_KEY` خالی در env
- **When** `npm run assistant:key` اجرا شود
- **Then** no-op تمیز با پیام روشن (بدون MODULE_NOT_FOUND).
- **نگاشت تست:** اجرای واقعی — exit 0 ✅

## AC-08 — محافظ JWT در production
- **Given** `NODE_ENV=production`
- **When** `JWT_SECRET` غایب/ضعیف/پلیس‌هولدر باشد
- **Then** سرور عمداً بالا نمی‌آید (FATAL + exit 1)؛ با راز قوی بالا می‌آید.
- **نگاشت تست:** اجرای واقعی با هر دو مقدار — سبز ✅

## AC-09 — خروج، کش سرویس‌ورکر را پاک می‌کند
- **Given** کاربر واردشده با SW فعال
- **When** logout انجام شود
- **Then** پیام `CLEAR_SHELL` به SW می‌رود و کش‌ها پاک می‌شوند؛ خروج در نبود SW هم نمی‌شکند.
- **نگاشت تست:** بازرسی کد + bump نسخه (`hosp-v13`)؛ **تست مرورگری خودکار: unverified** (نیاز به SW فعال در headless کامل — در محیط فعلی مرورگر بدون controlled SW اجرا می‌شود)

## AC-10 — داکر بالا می‌آید (ایستا)
- **Given** `docker-compose.yml`
- **When** سرویس‌ها ساخته/راه‌اندازی شوند
- **Then** فایل مرجع nginx وجود دارد (`docs/nginx.conf`) و متغیرهای اجباری مستندند.
- **نگاشت تست:** بازرسی وجود فایل ✅؛ **`docker compose up` واقعی: unverified** (docker در این محیط نیست)

## کارهای باز (به معیار تبدیل‌نشده)
- ماتریس AC-11 (IDOR کامل per-endpoint): طراحی‌شده اما تست خودکار ندارد → **unverified**
- Lighthouse / a11y عددی → **not measured** (ابزار در محیط نبود)
- دیپلوی preview/production → **blocked** (بدون provider؛ نیاز تصمیم مالک)
